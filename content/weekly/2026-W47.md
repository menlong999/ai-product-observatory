# AI Product Observatory · 2026-W47：从 Agent 写完，转向怎么验收

发布日期：2026-11-22（Asia/Shanghai）。窗口：北京时间 11 月 16 日至 22 日本次核查；不是全周结束后的完整市场统计。

## 本周 Top 3

1. **验收进一步脱离实现。** TestSprite 展示“两条 PR 分别绿、合并后失败”；StateWeave 用可重置应用状态测 Agent；Appxiom 补线上故障证据。它们分别回答规格、模拟状态、真实复现三个问题。
2. **持久运行转向恢复与账单。** OpenComputer 自 W35 再现，Maritime 补休眠、唤醒和每 Agent 限额；Mastra Factory 用长会话和分阶段 PR 交付把运行时接上团队协作。速度、恢复和完成不等价。
3. **Agent 输出变多之后，要把证据连到代价。** StarSling 把 CI 优化与基准一起提交，说明可审阅性比“自动变快”更有价值；本地容量 canfit 与录音流程 Bluedot 提供更窄、可直接检查的产品对照。

## 本周 Top 9 产品

### 1. TestSprite 4.0
- 来源、日期与分类：[Product Hunt 1](https://www.producthunt.com/products/testsprite) · [官方 2](https://www.testsprite.com/blog/introducing-testsprite-4-0)；2026-11-19（发布或讨论日，平台原标注）；规格驱动 QA / 浏览器回归。
- 产品：把需求、票据或规格变成真实浏览器测试，向 PR 回传失败证据。
- 讨论与发布信号（11 月 22 日快照）：PH 11/19 日榜第 1、373 points；周榜样本第 5。厂商展示 10 行规格生成 29 项测试，在两条分别通过 CI 的 PR 合并后捕获植入回归。
- 创作者背景：由发布作者 Yunhao Jiao 解释 coding agent 修一处坏一处与 QA 如何独立验收。
- 为什么重要 / 可借鉴：让测试依据来自业务规格而不只是现有实现，记录规格版本与实际被测构建。
- 中国本地化机会（研究假设）：适合企业 Web 验收；先做中文规格证据链和内网测试账号，再谈自动修改。
- 边界：演示为厂商构造，不是公开 held-out 跨项目基准或客户故障率。
- 值得写：Yes。

### 2. StateWeave
- 来源、日期与分类：[Product Hunt 1](https://www.producthunt.com/products/stateweave)；2026-11-16（发布或讨论日，平台原标注）；有状态 Agent 仿真。
- 产品：为 Agent 提供带一致数据的业务应用副本，重置状态、注入常见故障并按实际调用与断言记分。
- 讨论与发布信号（11 月 22 日快照）：PH 当日第 12；产品页有制作者原始描述。持续同步真实环境仍为规划。
- 创作者背景：团队以应用副本替代空转 mock；独立官网未能从本环境读到正文。
- 为什么重要 / 可借鉴：让多工具共享状态并评最终状态，同时验证权限失败与重试。
- 中国本地化机会（研究假设）：可从国产 ERP/IM 的少数读取接口做合成 twin，先解决权限和版本。
- 边界：未测 API 完整性、跨租户隔离或复刻误差；不能视为所有应用与真实环境等价。
- 值得写：Yes。

### 3. Appxiom
- 来源、日期与分类：[Product Hunt 1](https://www.producthunt.com/products/appxiom) · [官方 2](https://www.appxiom.com/announcements/appxiom-agent-skills-and-mcp-server)；2026-11-17（发布或讨论日，平台原标注）；生产故障上下文。
- 产品：把移动和 Web 的崩溃、冻结、网络和流程故障组织成 coding agent 能查询的上下文。
- 讨论与发布信号（11 月 22 日快照）：PH 日榜第 4；W47 周榜样本第 11、297 points。技能和 MCP 发布早于本周，本周增量为传播。
- 创作者背景：团队强调按受损业务目标排序，未见可复核客户收益。
- 为什么重要 / 可借鉴：把症状、复现条件与版本连起来，避免同时让修复 Agent 充当唯一裁判。
- 中国本地化机会（研究假设）：先做 App 线上错误到只读复现包，敏感字段在提供给模型前裁剪。
- 边界：产品自述，不证明全栈根因均可推断、问题已修复或营销排名可外推采用率。
- 值得写：Maybe。

### 4. OpenComputer
- 来源、日期与分类：[Hacker News 1](https://news.ycombinator.com/item?id=50581403) · [官方 2](https://docs.opencomputer.dev/getting-started/architecture) · [官方 3](https://opencomputer.dev/blog/cloud-agents-as-fast-as-local/) · [官方 4](https://opencomputer.dev/blog/opencomputer-open-source-devin-alternative/)；2026-11-20（发布或讨论日，平台原标注）；持久 Agent 工作空间。
- 产品：持久团队 VM 与 rootless Podman 工作隔离，支持 Git 分支/worktree、按轮快照和恢复。
- 讨论与发布信号（11 月 22 日快照）：Show HN 116 points、36 comments；官网首发是 11 月 13 日，早于本轮；厂商此前窄基准称中位 24 秒首次推送、56 秒四 PR 绿、6 次中完成 5 次。
- 创作者背景：本观察 W35 已有旧记录；本周是团队工作区与恢复机制再验证，不是首次出现。
- 为什么重要 / 可借鉴：分开测恢复时间、工作区权限和已验收完整结果，不能用第一次 push 代替完成。
- 中国本地化机会（研究假设）：可从国内自托管研发环境的临时 worktree、审阅和接管做小范围试验。
- 边界：作者基准的任务与计时口径狭窄；未验证不同负载/团队的端到端吞吐。
- 值得写：Yes。

### 5. Maritime
- 来源、日期与分类：[Hacker News 1](https://news.ycombinator.com/item?id=50549188) · [官方 2](https://maritime.sh/)；2026-11-18（发布或讨论日，平台原标注）；Agent 云 / 生命周期。
- 产品：在可保留状态的 microVM 上提供休眠/唤醒、事件触发、恢复与每 Agent 限额。
- 讨论与发布信号（11 月 22 日快照）：Launch HN 60 points、66 comments；厂商的 2 GB 实例起价样例不含模型与完整运营开支。
- 创作者背景：共同创始人 Ary 和 Maria 称痛点不只是隔离，还有更新、路由和恢复。
- 为什么重要 / 可借鉴：区分空闲成本、激活延迟、磁盘留存、失败恢复，以及不再需要时的停止责任。
- 中国本地化机会（研究假设）：国内可先针对低占用的定时 Agent 测同一负载的休眠、恢复及触发成本。
- 边界：官方方案与作者说法，不是生产 SLA 或综合成本比较；未审计权限。
- 值得写：Yes。

### 6. Mastra Factory
- 来源、日期与分类：[Hacker News 1](https://news.ycombinator.com/item?id=50548660) · [GitHub 2](https://github.com/mastra-ai/template-factory)；2026-11-18（发布或讨论日，平台原标注）；开源软件交付工作流。
- 产品：把长会话 Agent、Slack、PR 反馈及共享知识接入分阶段的交付看板。
- 讨论与发布信号（11 月 22 日快照）：Show HN 156 points、44 comments；团队自报一周 Factory 创建并合并 238 PR，人类合并 630 PR。
- 创作者背景：Shane、Sam、Abhi 把内部维护流程做成开源模板；具体阶段可配置。
- 为什么重要 / 可借鉴：对任务逐步留下证据与责任，不把 Agent PR 数当成生产力。
- 中国本地化机会（研究假设）：可从企业 IM 事项到内部 Git 的可审阅交付链做集成，保留人工变更控制。
- 边界：PR 范围和规模不等，未控制人工 review、返工和生产事故；另一些 harness 仍在接入计划中。
- 值得写：Yes。

### 7. StarSling
- 来源、日期与分类：[Hacker News 1](https://news.ycombinator.com/item?id=50536468) · [GitHub 2](https://github.com/starsling-demo-org/benchmark-gogs)；2026-11-17（发布或讨论日，平台原标注）；CI 执行和基准 PR。
- 产品：高速 CI runner 加 agent 提交的优化 PR，用基准报告说明建议而非自动采纳。
- 讨论与发布信号（11 月 22 日快照）：Launch HN 89 points、53 comments；Gogs 公开复跑材料比较了选定任务，冷缓存、每侧 5 次取中位。
- 创作者背景：Yonas、Daniel 自述因内部 Agent 提交变多，CI 成了交付限制。
- 为什么重要 / 可借鉴：硬件、缓存与优化补丁分别给控制组；快不代表测试仍覆盖原失效模式。
- 中国本地化机会（研究假设）：可先做企业现有流水线耗时定位与带证据的提案，不必迁移所有 runner。
- 边界：公开 Gogs 对照是 runner 与补丁组合效应，不能单独归因 Agent；非独立普遍收益。
- 值得写：Yes。

## 跨周比较

- **连续出现：** OpenComputer W35 已收录，W38 Bitrise、W39 Solid/Sai、W40 Dots、W41 Pine、W42 Guilds 旁证、W44 Herdr（人操作入口）已经把持久运行写入观察。本周 OpenComputer 与 Maritime 补了按轮恢复、团队分支、空闲开支，不是新赛道或首次 OpenComputer。此前 W46 Docker Agent / Deep Agents 的语义与权限修复也不等于本周由其它产品带来的新增数据。
- **同类集中：** W41 Databench 可复现数据检查，W42 Tiden/Kerno 强调独立验收，W43 Sphinx/heal.dev 补验收与执行证据，W44 Tiden 将证据绑到具体构建、Faylee 记录故障现场，W46 Plurai/three.dev 将目标变成最终状态或线上故障修复。W47 TestSprite/StateWeave/Appxiom 分别补规格、拟真状态、线上上下文，不是一种软件的三个名字；StarSling 则把优化变成带基准的 PR。
- **首次观察：** 在上述已有方向里，跨 PR 合并后才出现的浏览器回归、本周 HN 上可拆分的 CI 优化 PR，以及可售前核查的本地模型容量估计，提供不同的切入点。除仓库历史明确覆盖的 OpenComputer 外，“首次”仅指本轮所查历史未见，不是产品首发或世界首创。Bluedot 本周是产品版本与采纳讨论，不由电话录制推出新类别。
- **持续升温：** 当前样本中，独立验收、可复现状态和真实故障证据仍在积累，长任务运行也重新获得明确的新案例；这里是工程证据密度，不是市场份额、收入、留存或生产提效。
- **证据趋弱：** W46 Kapso/AgentRun/Omnigraph 的版本化经验与知识，本周没有同强度的新增公开产品对照；LangChain 知识工厂的维护流程只是相邻证据，未证实同产品的自我改进或权重变化。减少主表篇幅，不判定市场下滑。
- **暂离一级观察：** 维持 W41–W46 结论，不把独立 Agent FinOps 提升为已成立品类。LangSmith 的 PR 成本归属和 Maritime 的生命周期预算体现嵌入现有流程，没提供独立成本产品的留存或付费证据；产品档案仍保留。泛规格神器不因单次浏览器演示就重列一级。

## 判断修正

- 之前（W44）主要问“绿灯是否对应这个构建”；本周扩展为“哪个规格版本、哪个合并产物、哪个状态快照构成可复核绿灯”。TestSprite 的演示是可解释反例，未证明真实团队缺陷率普遍降低。
- 之前（W41/W42）把持久环境优先衡量为能否恢复；本周建议再看恢复后是否继续同一工作区、是否按授权恢复、空闲成本和完整交付能否分别计量。OpenComputer/Maritime 是技术证据，仍没有可比完整成功率。
- 未修正“PR/生成量不能代替可验收产出”。新 PR 数只有提供关联目标、人工审查、回退和复发后才适合作团队决策。未获得足以更新市场份额或商业验证的证据。

## 下周继续观察

- QA：同一业务规格在两个单独通过但合并失败的变更上复跑，记录规格、测试与构建版本及人工裁定；区分产品演示与真实缺陷。
- 持久运行：复跑冷启动、休眠唤醒、超时与权限撤销；分别计磁盘、流量和模型成本。
- 真实故障回流：拿到最小故障现场后，看能否固定证据重放，以及更改后是否由另一版本的用例复核。只按市场热度不升级任何产品。
- 独立产品：补查收入/续费、真实使用和中文边界；没有公开数值就保留未证实。
